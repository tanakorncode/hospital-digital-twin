# ผังโรงพยาบาลแบบตั้งค่าได้ทั้งหมด (Facility Model) — เอกสารออกแบบ

ร่าง 18 ต.ค. 2026 · สถานะ: **รออนุมัติก่อนลงมือ**

> เป้าหมาย: อาคาร/ตึก → ชั้น → แผนก → กลุ่มบริการ → ห้อง/ช่องบริการ ตั้งค่าได้ทั้งหมดจากหน้าเว็บ เปิด–ปิดได้ทุกระดับ ค้นหาได้
> และ **ทั้งระบบใช้ข้อมูลชุดเดียวกัน** (แผนที่ 3D, คิว, จอทีวี, ตัวจำลอง, จอง/นัด, ตารางแพทย์, นำทาง, ตู้ต้อนรับ, รายงาน, สิทธิ์รายแผนก) — ไม่มีผังเขียนตายตัวในโค้ด

## 1. สภาพปัจจุบัน (สิ่งที่ต้องเลิก)

| ส่วน | ตอนนี้ | ปัญหา |
|---|---|---|
| อาคาร 5 หลัง, ตำแหน่ง/ขนาด, จำนวนชั้น | `apps/web/lib/scene-data.ts` (`buildings`) | เพิ่ม/แก้ไม่ได้ |
| แผนกรายชั้นทุกอาคาร | `buildingStats` ในไฟล์เดียวกัน | แก้ได้เฉพาะ OPD ชั้น 2–4 ผ่าน "layout" (เพิ่ม/เปลี่ยนชื่อ/แบ่งห้อง) |
| ห้องตรวจ | คำนวณ "6 ห้องต่อชั้น แบ่งเท่า ๆ กัน" จากความกว้างอาคาร (`floorRooms`) | จำนวนห้องต่อชั้นตายตัว |
| ช่องซักประวัติ | คำนวณจากจำนวนห้อง (`screeningCounters`) | กำหนดเองไม่ได้ |
| จุดบริการร่วม (ลงทะเบียน ห้องยา การเงิน เจาะเลือด เอกซเรย์ ER) | `counters` ใน `lib/queue.ts`, `labStationSpots`, `xrayRoomSpots` | จำนวนช่องตายตัว |
| ตู้คิว, เตียงหอผู้ป่วย, เตียง ER | `kiosks`, `wardBeds`, `erBedSpots` | ตายตัว |
| รหัส | `opd-2-0` (คลินิก), `opd-201` (ห้อง), `screen:opd-2-0:2`, `counter:pharmacy:3` | รหัสสร้างจาก "ตำแหน่ง" → ย้าย/แทรกแล้วรหัสเลื่อน |
| ฝั่ง API | ตรวจรูปแบบรหัสด้วย regex (`opd-\d-\d`, `opd-\d{3}`) ใน booking / appointment / visits / auth / queue | ของใหม่ที่รหัสไม่ตรงรูปแบบใช้ไม่ได้ |

ผังกระจายอยู่ใน 16 ไฟล์ฝั่งเว็บ + 6 ไฟล์ฝั่ง API

## 2. หลักการ

1. **แหล่งความจริงเดียว** — ผังเก็บในฐานข้อมูลฝั่ง API, ทุกหน้าจอและทุก service อ่านจากที่เดียว (หน้าเว็บได้ snapshot พร้อมเลขเวอร์ชัน)
2. **รหัสคงที่ ไม่ผูกกับตำแหน่ง** — สร้างครั้งเดียวตอนเพิ่ม เปลี่ยนชื่อ/ย้าย/เรียงใหม่ได้โดยรหัสไม่เปลี่ยน ของเดิมคงรหัสเดิม (`opd-2-0`, `opd-201` …) เพื่อให้การจอง นัด ตารางแพทย์ ป้าย QR คิว ยังชี้ที่เดิม
3. **ไม่ลบจริงเมื่อมีของอ้างถึง** — "ปิด" = ชั่วคราว (วันนี้ไม่ใช้), "เลิกใช้" = เก็บถาวร (ประวัติยังอ่านได้) · ลบจริงได้เฉพาะของที่ไม่มีอะไรอ้างถึง
4. **ร่าง → เผยแพร่** — แก้หลายอย่างเป็นร่าง เห็นผลกระทบก่อน แล้วเผยแพร่เป็นเวอร์ชันใหม่ครั้งเดียว (มี audit, ย้อนเวอร์ชันได้)
5. **แต่ละกลุ่มมีจำนวนห้อง/ช่องของตัวเอง** — เช่น ห้องตรวจศัลยกรรมมี 3 ห้อง ซักประวัติศัลยกรรมมี 2 ช่อง ห้องยามี 5 ช่อง · ตั้งค่าเพิ่ม/ลบได้ทุกเมื่อ
6. **ค้นหาได้ทุกระดับ** และเปิด–ปิดได้ทุกระดับ (ปิดอาคาร = ทุกอย่างในอาคารปิด)

## 3. โครงสร้างข้อมูล

สองแกน ใช้ข้อมูลชุดเดียวกัน — **สถานที่** (อาคาร › ชั้น) กับ **หน่วยงาน** (แผนก) มาพบกันที่กลุ่มบริการ:

```
สถานที่:   อาคาร (Building) ─┬─ ชั้น (Floor)
                             │
หน่วยงาน:  แผนก (Department, ไม่ผูกชั้น)
              └─ กลุ่มบริการ (Service Group) @ ชั้น…   ← "ห้องตรวจศัลยกรรม", "ซักประวัติศัลยกรรม", "ช่องจ่ายยา"
                   └─ จุดบริการ (Service Point)        ← "ห้องตรวจ 1", "ช่องบริการ 1", "เตียง 3" (ตั้งชั้นเองได้)
```

- **แผนก = หน่วยงาน**: ชื่อ อักษรคิว การรับจอง/นัด สิทธิ์เจ้าหน้าที่ รายงาน — **ไม่ผูกชั้น** แผนกเดียวจึงกระจายได้หลายชั้น/หลายอาคาร
- **ที่ตั้งอยู่ที่กลุ่มบริการ** (พื้นที่รอของกลุ่มอยู่ชั้นนั้น) และ **จุดบริการตั้งชั้นของตัวเองได้** (เช่น ห้องตรวจ 5 ของกลุ่มเดียวกันอยู่ชั้น 3)

### 3.1 อาคาร — `facility_buildings`
| ฟิลด์ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `id` | `opd`, `b_7k2m` | คงที่ |
| `name`, `shortName` | อาคารผู้ป่วยนอก, OPD | |
| `kind` | `opd` · `er` · `inpatient` · `diagnostics` · `support` · `other` | ใช้เลือกรูปแบบตั้งต้น/สีบนแผนที่ |
| `map` | `{x,z,width,depth,color}` | ตำแหน่ง/ขนาดบนแผนที่ 3D (ลากบนผัง 2D ได้) |
| `order`, `active`, `retiredAt` | | |

### 3.2 ชั้น — `facility_floors`
`id`, `buildingId`, `level` (… -1 = B1, 0 = G, 1, 2 …), `name` ("ชั้น 2" — แก้ได้), `description` ("ห้องตรวจอายุรกรรม"), `order`, `active`

### 3.3 แผนก/หน่วยงาน — `facility_departments`
| ฟิลด์ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `id` | `opd-3-0` (ของเดิม) / `d_9x1q` (ใหม่) | = "รหัสคลินิก" ที่การจอง/นัด/สิทธิ์รายแผนกใช้ |
| `name`, `shortName` | ศัลยกรรม | |
| `type` | `clinic` · `ward` · `emergency` · `diagnostic` · `service` · `support` | |
| `queuePrefix` | `D` | อักษรเลขคิว (ไม่ซ้ำกัน) |
| `features` | `{booking, appointments, walkIn}` | เปิดรับจอง/นัด/ผู้ป่วยหน้างาน |
| `firstGroupId` | ซักประวัติศัลยกรรม | ที่ผู้ป่วยไปรอหลังลงทะเบียน/เช็กอิน (ขั้นแรกของแผนก) |
| `order`, `active` | | |

### 3.4 กลุ่มบริการ — `facility_service_groups`
กลุ่มของจุดที่ "ให้บริการขั้นเดียวกัน คิวเดียวกัน" — นี่คือ **กลุ่มคิว** ของระบบคิว

| ฟิลด์ | ตัวอย่าง (ห้องตรวจ) | ตัวอย่าง (ซักประวัติ) | ตัวอย่าง (ห้องยา) |
|---|---|---|---|
| `id` | `exam:opd-3-0` (เดิม) | `screening:opd-3-0` (เดิม) | `counter:pharmacy` (เดิม) |
| `departmentId` | ศัลยกรรม | ศัลยกรรม | ห้องยา |
| `name` | ห้องตรวจศัลยกรรม | ซักประวัติศัลยกรรม | ช่องจ่ายยา |
| `floorId` | OPD ชั้น 3 | OPD ชั้น 3 | OPD ชั้น 1 |
| `zone` | ลำดับ/ความกว้างพื้นที่รอบนผังชั้น | | |
| `steps` | `exam`, `followup` | `screening` | `pharmacy` |
| `pointNoun` | **ห้องตรวจ** | **ช่องบริการ** | **ช่องบริการ** |
| `serves` | ผู้ป่วยของแผนกนี้ | ผู้ป่วยของแผนกนี้ | ทุกแผนก (จุดบริการร่วม) |
| `minOpen` | 1 | 1 | 1 |

`pointNoun` คือคำนามของจุดในกลุ่ม — ตอบโจทย์ "บางจุดใช้ ห้อง บางจุดใช้ ช่อง": เลือกได้ ห้องตรวจ · ห้อง · ช่องบริการ · ช่อง · เตียง · จุด · โต๊ะ หรือพิมพ์เอง

### 3.5 จุดบริการ — `facility_service_points`
| ฟิลด์ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `id` | `room:opd-301`, `screen:opd-3-0:2` (เดิม) / `p_4hq8` (ใหม่) | = สถานีคิว (station) |
| `groupId` | | |
| `number` | 1 | เรียงอัตโนมัติ แก้ได้ |
| `name` | (ว่าง = "{pointNoun} {number}") | ตั้งเองได้ เช่น "ห้องตรวจพิเศษ" |
| `roomCode` | 301 | เลขห้องจริงบนประตู (ไม่บังคับ) ใช้ประกาศเสียง/ป้าย |
| `floorId` | (ว่าง = ชั้นของกลุ่ม) | ห้องที่อยู่คนละชั้นกับกลุ่ม |
| `map` | ตำแหน่งบนผังชั้น (อัตโนมัติ/ลากได้) | |
| `active` | | ปิด = ไม่รับคิวใหม่ |

### 3.6 ตัวอย่าง: กลุ่มหนึ่งมีกี่ห้อง/กี่ช่องก็ได้ เพิ่ม/ลบได้
```
แผนกศัลยกรรม
 ├─ ซักประวัติศัลยกรรม   @ OPD ชั้น 3 → ช่องบริการ 1, ช่องบริการ 2            (2 ช่อง)
 └─ ห้องตรวจศัลยกรรม     @ OPD ชั้น 3 → ห้องตรวจ 1, ห้องตรวจ 2, ห้องตรวจ 3    (3 ห้อง · ปิดห้องตรวจ 3 ได้)
แผนกอายุรกรรม (กระจาย 2 ชั้น)
 ├─ ซักประวัติอายุรกรรม  @ OPD ชั้น 2 → ช่องบริการ 1–3
 ├─ ห้องตรวจอายุรกรรม    @ OPD ชั้น 2 → ห้องตรวจ 1–4
 └─ ห้องตรวจอายุรกรรม 2  @ OPD ชั้น 3 → ห้องตรวจ 5–6
แผนกห้องยา
 ├─ ช่องจ่ายยา           @ OPD ชั้น 1 → ช่องบริการ 1–5
 └─ ช่องจ่ายยา ชั้น 2    @ OPD ชั้น 2 → ช่องบริการ 1–2
```
ตอนตั้งค่า: กด "+ เพิ่มห้อง" / "+ เพิ่มช่อง" (ระบุจำนวนได้ เลขต่อให้เอง) หรือลบ/ปิดทีละห้อง · ห้อง/ช่องที่ยังมีอะไรอ้างถึง (ตารางแพทย์ คิววันนี้) ลบไม่ได้ ให้ปิดหรือเลิกใช้แทน

### 3.7 ของอื่นที่ย้ายเข้าผังด้วย
- **ตู้คิว/ตู้ต้อนรับ** → จุดบริการชนิด `kiosk` ที่ชั้นที่ตั้ง (ตำแหน่งบนผัง)
- **เตียงหอผู้ป่วย / เตียง ER** → กลุ่มบริการ `pointNoun=เตียง` ในแผนก ward/emergency
- **จุดนำทาง (QR)** → สร้างอัตโนมัติ 1 จุดต่อกลุ่มบริการ (ที่ตั้งจริง) + เพิ่มเองได้ (ลิฟต์ ห้องน้ำ) ไม่ต้องนำเข้าแยกอีก

## 4. ทั้งระบบใช้ข้อมูลชุดนี้อย่างไร

| ส่วนของระบบ | ใช้อะไรจากผัง | เดิม |
|---|---|---|
| แผนที่ 2D/3D | อาคาร (ตำแหน่ง/ขนาด/จำนวนชั้น), พื้นที่รอของแต่ละกลุ่มบนชั้นของกลุ่ม, จุดบริการวางตามผนังของชั้นตัวเอง | ค่าคงที่ใน scene-data |
| ระบบคิว | สถานี = จุดบริการ, กลุ่มคิว = กลุ่มบริการ, ขั้นตอนที่รับ = `steps` | `allStations()` สร้างจากสูตร |
| คอนโซลเจ้าหน้าที่ | ชื่อเต็ม, เปิด/ปิด, ตัวช่วยกระจายคิวภายในกลุ่ม | |
| จอทีวี `/tv` | รายการจอ = แผนก/กลุ่มบริการ | `screenDepts()` |
| ตัวจำลอง | สร้างผู้ป่วยตามแผนก/กลุ่มบริการ/จำนวนจุดที่เปิด | `opdClinics()` + ค่าคงที่ |
| จอง/นัด/ตารางแพทย์ | คลินิก = แผนกที่ `features.booking/appointments`, ห้องแพทย์ = จุดบริการ | regex `opd-\d-\d` |
| รับผู้ป่วย/เช็กอิน | แผนก + อักษรคิว → ไปรอที่ `firstGroupId` | |
| สิทธิ์รายแผนก | รหัสแผนก | regex |
| นำทาง/ตู้ต้อนรับ/LINE | ผู้ป่วยในคิว: ทางไปกลุ่มของขั้นถัดไป (และห้องที่เรียก) · ถามหาแผนก: บอกทุกชั้นที่แผนกนั้นมี ("อายุรกรรม: ชั้น 2 และชั้น 3") ให้เลือก | นำเข้าแยก |
| รายงาน | ชื่อ/ลำดับจากผัง | |

### 4.1 ผลต่อหน้าตาแผนที่ 2D / 3D
แผนที่ทั้ง 2D (ผังชั้น) และ 3D (มุมมองทั้งโรงพยาบาล/รายชั้น) **วาดจากผังชุดนี้** — เผยแพร่แล้วทุกจอที่เปิดอยู่เปลี่ยนตามทันที

| ตั้งค่า | แผนที่เปลี่ยนอย่างไร |
|---|---|
| เพิ่ม/ลบ/เลิกใช้อาคาร | มีตึกเพิ่ม/หายบนแผนที่ 3D · ป้ายชื่ออาคาร · ตัวเลือกอาคารในหน้าผังชั้น |
| ตำแหน่ง ขนาด สี ของอาคาร | ตึกย้ายที่/กว้าง-ลึก/สีเปลี่ยน · ลานรอบอาคาร ทางเดิน จัดตามใหม่ |
| จำนวนชั้น | ตึกสูง/เตี้ยลง (ซ้อนชั้นตามจำนวน) · ชื่อชั้นที่ตั้งเองแสดงบนป้าย |
| กลุ่มบริการบนชั้น (ลำดับ ความกว้าง) | พื้นที่รอของแต่ละกลุ่มเป็นแถบบนชั้นนั้น พร้อมชื่อ (เช่น "ห้องตรวจอายุรกรรม") |
| จำนวนห้อง/ช่องในกลุ่ม | กล่องห้องตามผนังด้านหลัง / โต๊ะช่องบริการหน้าพื้นที่รอ เพิ่ม-ลดตามจำนวน · ป้ายเลขห้องจริง (301) |
| ห้องที่ตั้งชั้นเอง | วาดบนชั้นนั้น (ห้องตรวจ 5 ของอายุรกรรมไปอยู่ชั้น 3) |
| เปิด/ปิด | ห้อง/ช่องที่ปิดเป็นสีจางลายเส้น · กลุ่มหรือแผนกที่ปิดเป็นพื้นที่สีเทา "งดให้บริการ" · ชั้น/อาคารที่ปิดจาง |
| ตู้คิว ตู้ต้อนรับ เตียง | วาดตามตำแหน่งในผัง |
| ผู้ป่วย/เจ้าหน้าที่ (ตัวจำลองและผู้ป่วยจริง) | เดินไปรอในพื้นที่ของกลุ่ม และเข้าห้อง/ช่องที่เรียก ตามผังใหม่ |

**การจัดวาง:** รอบแรกระบบจัดให้อัตโนมัติ — อาคารวางในที่ว่างของพื้นที่โรงพยาบาล, พื้นที่รอเรียงตามลำดับกลุ่ม, ห้องเรียงตามผนัง (ห้องมากจนผนังไม่พอ → ห้องแคบลง/ขึ้นแถวที่สอง และเตือนในหน้าตั้งค่า) · ระยะถัดไป (F4): ลากปรับตำแหน่งอาคาร พื้นที่รอ และห้อง บนผัง 2D ได้เอง

**ข้อจำกัด:** เป็นผังจำลองตามสัดส่วน ไม่ใช่แบบสถาปัตย์จริง — ถ้าโรงพยาบาลมีแบบแปลน (SVG/DXF) นำเข้าเป็นพื้นหลังผังชั้นได้ในอนาคต · สิ่งประกอบฉาก (ถนน ลานจอดรถ อาคารประกอบ) ย้ายเข้า "ผังพื้นที่โรงพยาบาล" ให้ตั้งค่าได้เช่นกัน (ตอนนี้ยังเขียนตายตัว) · หน้าแผนที่จริง (`/real-map`, ภาพดาวเทียม/OSM) ผูกอาคารในผังกับรูปตึกจริงได้ภายหลัง

ฝั่งเว็บจะมี **ตัวแปลงชั้นเดียว** (`lib/facility.ts`) ที่สร้างฟังก์ชันชุดเดิม (`buildings`, `floorRooms`, `opdClinics`, `allStations`, `counterServices` …) จากผังที่โหลดมา — โค้ดเดิมเปลี่ยนน้อยที่สุด แล้วค่อยย้ายไปใช้ผังตรง ๆ ทีละส่วน

## 5. การเก็บข้อมูลและ API

- ตาราง `facility_buildings`, `facility_floors`, `facility_departments`, `facility_service_groups`, `facility_service_points` (migration ใหม่) + `facility_versions` (เวอร์ชันที่เผยแพร่: เลข, ผู้เผยแพร่, เวลา, สรุปการเปลี่ยน)
- ร่างเก็บแยก (`facility_drafts`, 1 ร่างต่อผู้ดูแล) → **เผยแพร่** = ตรวจความถูกต้อง + บันทึกในทรานแซกชันเดียว + เพิ่มเวอร์ชัน + ส่ง `facility:updated` ให้ทุกหน้าจอ
- ตรวจก่อนเผยแพร่:
  - รหัส/อักษรคิวไม่ซ้ำ, ชื่อไม่ซ้ำในระดับเดียวกัน
  - แผนกที่เปิดต้องมีจุดที่เปิดอย่างน้อย `minOpen` ในทุกกลุ่ม · ทุกกลุ่ม/จุดต้องอยู่บนชั้นที่มีอยู่และเปิดอยู่
  - จะ "ลบ" ของที่มีอ้างถึงไม่ได้ (การจอง/นัดอนาคต, ตารางแพทย์, ป้าย QR, คิววันนี้) → เสนอ "เลิกใช้" แทน และบอกว่ามีอะไรอ้างถึงกี่รายการ
- ฝั่ง API เลิก regex: booking / appointment / visits / auth ตรวจว่า **รหัสมีอยู่ในผังและเปิดอยู่**
- คำสั่ง (ผู้ดูแลระบบ): `facility:get`, `facility:draft:save`, `facility:draft:discard`, `facility:impact`, `facility:publish`, `facility:versions`, `facility:rollback` · ทุกหน้าจอ (รวมจอสาธารณะ) ได้ snapshot ที่ตัดข้อมูลภายในออก

## 6. การย้ายข้อมูลเดิม (ไม่มีอะไรหลุด)

1. Migration สร้างผังเริ่มต้น **จากค่าคงที่ปัจจุบัน** ด้วยรหัสเดิมทุกตัว (`opd-2-0`, `room:opd-201`, `screen:opd-2-0:1`, `counter:pharmacy:1` …) → การจอง นัด ตารางแพทย์ (`room_id`), visits, ป้าย QR, สิทธิ์ผู้ใช้ ใช้ต่อได้ทันที
2. รวมค่าที่ตั้งไว้ใน "layout" (แผนกที่เพิ่ม, เปลี่ยนชื่อ, แบ่งห้อง, ชื่อห้อง, จุดที่ปิด) เข้าไปในผังเริ่มต้น แล้วเลิกใช้ "layout" (หน้า "แผนกและจุดบริการ" เดิมถูกแทนที่)
3. ค่าคงที่ใน `scene-data.ts` เหลือเป็น "แม่แบบโรงพยาบาลตัวอย่าง" ไว้ใช้ตอนติดตั้งครั้งแรก/เดโมเท่านั้น

### 7.2 ความสะดวก
- **ต้นไม้ซ้าย + รายละเอียดขวา** สลับมุมมอง "ตามแผนก" / "ตามสถานที่" ได้ · ค้นหาแล้วต้นไม้กรองพร้อมไฮไลต์คำ และเปิดกิ่งที่เจอให้เอง · ตัวกรอง เปิด / ปิด / มีปัญหา (เช่น กลุ่มที่ไม่มีจุดเปิด)
- **แม่แบบตอนเพิ่ม** — "เพิ่มแผนกผู้ป่วยนอก" สร้าง *ซักประวัติ{ชื่อ}* (ช่องบริการ ×2) + *ห้องตรวจ{ชื่อ}* (ห้องตรวจ ×2) ให้ทันที · เพิ่มอาคารเลือกชนิด → สร้างชั้นตามจำนวนที่ระบุ
- **เพิ่มทีละหลายจุด** — "+ เพิ่ม" ระบุจำนวน (เช่น 3) เลขต่อจากตัวสุดท้ายอัตโนมัติ · ตั้งเลขห้องจริงทีละช่วง (301–303)
- **เปิด/ปิดได้ทุกระดับ** ด้วยสวิตช์ (ปิดชั้น = ทุกแผนกในชั้นปิด) และกดชิปของจุดเพื่อสลับ
- **ลากเรียง** แผนก/กลุ่ม/จุด · **ย้าย** กลุ่มบริการไปชั้น/อาคารอื่นด้วยตัวเลือก "@ ชั้น" (ห้องย้ายตาม ยกเว้นห้องที่ตั้งชั้นเอง) · รหัสไม่เปลี่ยน
- **ร่าง + ดูผลกระทบ** ก่อนเผยแพร่: สรุปสิ่งที่จะเปลี่ยน, รายการที่อ้างถึง, คำเตือน (เช่น "ปิดห้องตรวจ 2 แล้ว — วันนี้มีคิวรอ 5 คน จะถูกเรียกจากห้องอื่นในกลุ่ม")
- **ผัง 2D ด้านข้าง** (แท็บ "ผังชั้น") เห็นตำแหน่งพื้นที่รอและจุดบริการทันทีที่แก้ ลากปรับตำแหน่งได้ (ระยะถัดไป)
- **ย้อนเวอร์ชัน** จากประวัติการเผยแพร่
